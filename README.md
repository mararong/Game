# 윷놀이

기획서 `윷놀이_게임_기획서.md`를 바탕으로 만든 정적 웹 게임입니다. HTML·CSS·JavaScript와 SVG만 사용하며, 게임 실행에는 패키지 설치·백엔드·외부 AI API가 필요하지 않습니다.

## 바로 실행하기

`index.html`을 Chrome, Edge, Firefox, Safari 등 최신 브라우저로 열면 됩니다. 파일을 더블클릭해서 실행할 수 있고, 다섯 개의 게임 파일을 함께 두면 오프라인으로도 플레이할 수 있습니다.

로컬 서버를 선호한다면 Node.js 18 이상에서 다음을 실행하세요. 의존성 설치는 필요하지 않습니다.

```sh
npm start
```

브라우저에서 <http://localhost:4173>에 접속합니다. 서버는 현재 컴퓨터의 루프백 주소에만 바인딩합니다. 종료는 터미널에서 Ctrl+C를 누르세요.

정적 웹 호스팅에는 `index.html`, `style.css`, `rules.js`, `ai.js`, `game.js` 다섯 파일을 같은 폴더에 올리면 됩니다.

## 다른 컴퓨터·모바일에서 열기

### 같은 Wi-Fi에서 바로 열기

게임 파일이 있는 컴퓨터에서 다음을 실행합니다.

```sh
npm run start:lan
```

터미널에 표시되는 `http://192.168.x.x:4173` 또는 `http://10.x.x.x:4173` 형태의 주소를 같은 Wi-Fi에 연결한 다른 컴퓨터·휴대폰·태블릿의 브라우저에서 엽니다. 접속 주소는 실제 네트워크 환경에 맞게 출력됩니다. 이 방법은 게임을 실행하는 컴퓨터가 켜져 있고 서버가 실행 중이어야 합니다. 각 기기에서 별도의 한 판이 실행됩니다.

접속이 안 되면 두 기기가 같은 네트워크인지 확인하고, Windows 방화벽에서 Node.js의 개인 네트워크 연결을 허용하세요. `npm start`는 기존처럼 현재 컴퓨터에서만 접속할 수 있습니다.

### 인터넷 주소로 열기: GitHub Pages

저장소: [mararong/Game](https://github.com/mararong/Game)

최초 1회 [저장소 Settings → Pages](https://github.com/mararong/Game/settings/pages)에서 Build and deployment의 Source를 **GitHub Actions**로 선택합니다. 그런 다음 [Actions](https://github.com/mararong/Game/actions)에서 **Verify and deploy Yutnori → Run workflow → main**을 실행합니다. 이후 main에 푸시하면 테스트와 배포가 자동으로 진행됩니다.

배포가 성공하면 `https://mararong.github.io/Game/`에서 컴퓨터가 꺼져 있어도 PC·모바일 브라우저로 게임을 열 수 있습니다. 이 주소는 Pages 설정과 배포가 완료된 뒤 사용할 수 있으며, 설정 전에는 404가 표시됩니다.

현재 Game 저장소는 비공개입니다. 비공개 저장소의 Pages 사용에는 이를 지원하는 GitHub 요금제가 필요합니다. [GitHub 공식 Pages 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages#availability-of-github-pages)를 참고하세요. 공개 범위는 이번 작업에서 변경하지 않습니다. 현재 요금제에서 Pages를 지원하지 않으면 아래 정적 파일을 다른 정적 웹 호스팅에 올리거나 같은 Wi-Fi 접속 방법을 사용할 수 있습니다.

배포 전에 파일만 만들려면 다음을 실행합니다.

```sh
npm run build
```

생성된 `dist/`에는 게임 파일 다섯 개와 `.nojekyll`만 들어갑니다. 기획서·테스트·개발 서버는 웹사이트에 배포하지 않습니다.

인증 토큰이나 별도 외부 AI API 키는 필요하지 않습니다. GitHub Actions는 저장소의 기본 토큰으로 배포합니다.

## 플레이 방법

1. 개인전(2~4인) 또는 2대2 팀전을 고릅니다.
2. 이름과 사람/AI를 정합니다. 새 슬롯은 미설정이며 ‘빈자리 AI로 채우기’로 한 번에 채울 수 있습니다. 최소 한 명은 사람이어야 합니다.
3. ‘윷 던지기’를 누릅니다. 윷·모가 나오면 추가로 던진 후 결과를 사용합니다.
4. **이동 결과 → 말 → 도착점** 순서로 고릅니다. 경로 버튼을 누르면 이동이 확정됩니다. 보드의 작은 말을 직접 누르지 않고도 아래 버튼만으로 전부 조작할 수 있습니다.
5. 네 개의 말을 모두 완주하면 승리합니다. 팀전은 팀당 네 개의 공유 말을 사용합니다.

잡기·업기·지름길·지나온 경로를 되짚는 빽도·2.5% 낙·쌓인 결과·추가 던지기를 지원합니다. 사람과 AI는 같은 규칙 함수와 확률을 사용합니다. AI는 외부 서비스 없이 합법 행동을 평가해 선택합니다.

규칙 보기와 다시 시작 확인 창을 열면 진행을 일시 정지하며, 닫거나 취소하면 이어집니다. 다시 시작하면 이전 게임의 AI와 던지기 타이머를 취소합니다. 대화상자는 Escape로 닫을 수 있습니다.

온라인 대전·로그인·랭킹·진행 저장은 없습니다. 새로고침하면 초기화됩니다.

## 파일 구조

| 파일 | 역할 |
| --- | --- |
| `index.html` | 시작·설정, 게임 화면, 대화상자 구조 |
| `style.css` | PC·모바일 화면, 말·윷·경로 스타일, 동작 줄이기 지원 |
| `rules.js` | 보드 연결, 경로 이력, 합법 행동, 잡기·업기·완주·차례·확률 |
| `ai.js` | 사전식 행동 평가와 확률 가중 잡힘 위험 추정 |
| `game.js` | SVG 및 HTML 렌더링, 사용자 입력, AI 예약, 일시 정지·재시작 |
| `server.js` | 현재 컴퓨터 또는 같은 Wi-Fi 기기에서 접속하는 정적 서버 |
| `scripts/build-static.js` | 정적 호스팅용 게임 파일만 dist/로 묶기 |
| `.github/workflows/deploy-pages.yml` | 자동 검사·테스트·GitHub Pages 배포 |
| `tests/rules.test.js` | 규칙·AI·32판 완주 시뮬레이션 검증 |
| `tests/controller.test.js` | 가상 시계와 DOM 대역을 사용한 입력·타이머·대화상자 제어 검증 |
| `tests/hosting.test.js` | 정적 배포 묶음·현재 기기 서버·LAN 서버 검증 |

## 검증

Node.js 18 이상에서 설치 없이 실행합니다.

```sh
npm test
npm run check
```

37개 테스트가 설정 검증, 팀 순서, 윷 면 16개 조합, 낙·빽도, 지름길, 경로 이력 병합, 업힌 말의 이동·포획·완주, 승리 즉시 종료, AI 합법 행동, 중복 입력 방지, 대화상자의 일시 정지·재개, 재시작 후 오래된 타이머 취소를 확인합니다. 개인전 2·3·4인과 팀전의 32판 시뮬레이션, 정적 배포 파일 구성, 로컬·LAN 서버의 파일 접근 범위 검증도 포함합니다.

컨트롤러 테스트는 실제 브라우저 레이아웃·터치·네이티브 초점 가두기를 검증하지 않습니다. 개발 환경에서 브라우저 연결과 헤드리스 렌더링 프로세스가 동작하지 않아, 실제 화면의 시각 검증은 수행하지 못했습니다. 반응형 CSS는 320px부터 데스크톱까지 대응하도록 작성했습니다.

개발 전용 `YutRules.outcomeFor()`로 고정된 결과를 만들 수 있습니다. 강제 결과 선택은 사용자 화면에 제공하지 않습니다. 기본 낙 확률은 `rules.js`의 `NAK_PROBABILITY` 상수에서 관리합니다.
